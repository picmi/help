# Configure file, finance, and table questions

Some question types have additional settings that define the answer format. Choose these settings carefully so the
information participants provide is consistent and easier to review.

## File questions

Choose **File** when participants must upload evidence or another document. File questions can define accepted file
categories and whether at least one file is required.

The current accepted file types include:

- **JPEG**, **PNG**, **JPG**, and **HEIC** images
- **PDF** documents
- **Word** documents
- **Google Docs** documents
- **ODS** spreadsheets

Select the file types that match the evidence you expect. Do not describe a file as a passport, licence, or photo ID
category unless the question prompt explains the document; PICMI configures acceptance by file type.

::: instructions

1. Create or edit a question.
2. Choose **File** as the **Question type**.
3. Select the accepted file categories.
4. Set whether at least one file is required.
5. Check the question preview.
6. Save the question.

:::

## Finance question profiles

Finance questions use a base question type plus a more specific profile. Available profiles are:

| Profile                   | Use it for                                |
|---------------------------|-------------------------------------------|
| **NZ bank account**       | A New Zealand bank account.               |
| **AU bank account**       | An Australian bank account.               |
| **AU BSB / bank routing** | An Australian BSB or bank-routing answer. |
| **NZ IRD number**         | A New Zealand IRD number.                 |
| **AU TFN / tax number**   | An Australian TFN or tax number.          |

Choose the correct country-specific profile because it determines the appropriate answer format and validation
expectations.

## Table question profiles

Table questions use a predefined table profile. They are structured forms for consistent collection and later review,
not ordinary free-text questions.

| Profile                                                      | Purpose and example                                                                                                                                                           |
|--------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Profile services / Orchard Profile and Services Required** | Collect orchard identity, blocks, KPIN, varieties, region, maturity, size, yield, canopy, address, and services required. Use it for an orchard profile and service proposal. |
| **GRASP social practices**                                   | Collect social-practice areas and descriptions of policies or processes. Use it for GRASP-related information.                                                                |
| **Pay Rates**                                                | Collect services, client contract rates, employee pay rates, and rate type such as hourly, piece-rate, or percentage.                                                         |
| **Subcontractors list**                                      | Collect subcontractor name, services provided, GLOBALG.A.P./CAV number, and CAV expiry.                                                                                       |

::: instructions

1. Create or edit a question.
2. Choose **Table** as the **Question type**.
3. Select the appropriate table profile.
4. Review the question preview and the fields the profile collects.
5. Save the question.

:::

## Example

For a kiwifruit services workflow, use **Profile services / Orchard Profile and Services Required** for the grower's
orchard details, **Pay Rates** for agreed rates, and **Subcontractors list** when subcontracted work must be recorded.

## Common mistakes

- Choosing a country profile that does not match the participant's bank or tax jurisdiction.
- Using Text when a Table profile is available for repeated structured information.
- Marking a file question optional when the workflow cannot continue without the document.
- Assuming a file category accepts every file format.
